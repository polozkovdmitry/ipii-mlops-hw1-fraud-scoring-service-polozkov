# Скоринг фродовых транзакций из Kafka

_NB! ниже написано с помощью ИИ, но я перепроверял и по максимому убирал неестественность языка. Надеюсь не слишком вырвиглазно получилось_

Сервис скоринга транзакций на основе семинарского проекта mts25_mlops_hw2_real_time_fraud_detection. Транзакции в формате test.csv из соревнования teta-ml-1-2025 читаются из топика Kafka transactions, проходят препроцессинг, скорятся моделью CatBoost на CPU, и результат пишется в топик scores в формате (transaction_id, score, fraud_flag). Модель осталась той же, что и на семинаре, за исключением трешхолда бинаризации для наглядности работоспособности.

# Запуск

Требования: Docker 20.10+ и Docker Compose v2, а также свободные порты 8080, 8501, 9095 и 2181.

    git clone <URL-репозитория>
    cd fraud-scoring-service
    docker compose up --build


Далее открываем http://localhost:8501, загрузить CSV в формате test.csv (пример лежит в misc/test_20.csv -- я взял первые 20 строк) и нажать «Отправить». Лучше брать небольшие файлы, на полном test.csv обработка идёт долго. Результаты видны в Kafka UI на http://localhost:8080, в топике scores. Без интерфейса данные можно отправить скриптом: python scripts/send_sample.py misc/test_20.csv (нужны kafka-python и pandas). Логи сервиса: docker compose logs -f fraud_detector. Остановка: docker compose down.

# Отличия от семинарского кода и улучшения

Не нужен train.csv. На семинаре при каждом старте контейнера читался весь train.csv (145 МБ), только чтобы получить таблицы кодирования категорий. В GitHub такой файл не залить (лимит 100 МБ), к тому же старт был медленным. Теперь эти статистики посчитаны один раз скриптом scripts/build_artifacts.py и лежат в fraud_detector/artifacts/preproc_artifacts.pkl (64 КБ). Результат препроцессинга я сверил со старым кодом на всём test.csv, признаки совпадают полностью.

Препроцессинг теперь работает с пачкой строк и использует готовые словари из артефактов. Раньше на каждое сообщение заново делались merge с train данными и обсчёт имьютера.

Kafka теперь умеет читать пачками (до 100 сообщений), скоринг и flush делаются один раз на пачку, а не на каждое сообщение. Если пачка падает, её обрабатываем по одной строке, чтобы одна плохая запись не ломала остальные; невалидный JSON просто пропускается с записью в лог.

Выходное сообщение теперь один JSON-объект, а не массив из одного объекта, как было из-за to_json(orient='records'). Так сообщение соответствует формату из задания (три поля) и любой потребитель топика может читать его напрямую, без распаковки списка. Топик называется scores, как в задании, чтобы название не расходилось с требованиями. На вход, кроме формата {"transaction_id": ..., "data": {...}} от интерфейса, принимается и просто строка test.csv, тогда id генерируется. Это нужно, чтобы сервис можно было проверить, отправив в топик строку из test.csv любым способом, не только через наш интерфейс.

Порог фрода вынесен в переменную окружения FRAUD_THRESHOLD в docker-compose.yaml. По умолчанию 0.05, это средний скор на test.csv, при нём около 18% транзакций получают fraud_flag = 1, и результат не выглядит пустым. Порог из соревнования был 0.98, при нём помечается около 0.4%. Чтобы поменять, достаточно исправить значение и выполнить docker compose up -d fraud_detector, пересборка не нужна.

Код скоринга модифицирован, что predict_proba вызывается один раз вместо двух, и убран print на каждое сообщение.

В docker-compose сервисы теперь стартуют после того, как Kafka реально готова (healthcheck), а не просто после запуска контейнера, а образ kafka-ui закреплён на версии вместо latest.
