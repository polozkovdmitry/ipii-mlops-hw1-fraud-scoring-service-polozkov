# Скоринг фродовых транзакций из Kafka

_NB! ниже написано с помощью ИИ, но я перепроверял и по максимому убирал неестественность языка. Надеюсь не слишком вырвиглазно получилось_

Сервис скоринга транзакций на основе семинарского проекта mts25_mlops_hw2_real_time_fraud_detection. Транзакции в формате test.csv из соревнования teta-ml-1-2025 читаются из топика Kafka transactions, проходят препроцессинг, скорятся моделью CatBoost на CPU, и результат пишется в топик scores в формате (transaction_id, score, fraud_flag). Отдельный сервис score_writer читает этот топик и складывает результаты в Postgres, а в интерфейсе по кнопке «Посмотреть результаты» можно увидеть последние фродовые транзакции и гистограмму скоров. Модель осталась той же, что и на семинаре, за исключением трешхолда бинаризации (для наглядности работоспособности сильно занижен).

# Запуск

Требования: Docker 20.10+ и Docker Compose v2, а также свободные порты 8080, 8501, 9095 и 2181. Postgres наружу не публикуется, он доступен только внутри docker-сети ml-scorer.

    git clone https://github.com/polozkovdmitry/ipii-mlops-hw1-fraud-scoring-service-polozkov.git
    cd ipii-mlops-hw1-fraud-scoring-service-polozkov
    docker compose up --build


Далее открываем http://localhost:8501, загрузить CSV в формате test.csv и нажать «Отправить». Для проверки лежат два примера, оба взяты из test.csv: misc/test_20.csv (первые 20 строк, для быстрой проверки) и misc/test_382.csv (382 строки, пачка среднего размера). Лучше брать небольшие файлы, на полном test.csv обработка идёт долго. Результаты видны в Kafka UI на http://localhost:8080, в топике scores, а также в самом интерфейсе: ниже на странице есть раздел «Результаты скоринга», по кнопке «Посмотреть результаты» показываются 10 последних транзакций с fraud_flag = 1 и гистограмма скоров. Гистограмму можно строить либо по последним 100 транзакциям, либо по всей последней отправленной пачке (последнюю пачку интерфейс помнит, пока страница не перезагружена). Скоры появляются в базе не мгновенно, поэтому если сразу после отправки результатов нет, нужно чуть подождать и нажать кнопку ещё раз.

Без интерфейса данные можно отправить скриптом: python scripts/send_sample.py misc/test_20.csv (нужны kafka-python и pandas). Логи сервисов: `docker compose logs -f fraud_detector` и `docker compose logs -f score_writer`. Остановка: `docker compose down` (накопленные в Postgres результаты при этом сохраняются, чтобы удалить и их, нужно `docker compose down -v`).

# Отличия от семинарского кода и улучшения

1. Не нужен train.csv. На семинаре при каждом старте контейнера читался весь train.csv (145 МБ), только чтобы получить таблицы кодирования категорий. В GitHub такой файл не залить (лимит 100 МБ), к тому же старт был медленным. Теперь эти статистики посчитаны один раз скриптом scripts/build_artifacts.py и лежат в fraud_detector/artifacts/preproc_artifacts.pkl (64 КБ). Результат препроцессинга я сверил со старым кодом на всём test.csv, признаки совпадают полностью.
2. Препроцессинг теперь работает с пачкой строк и использует готовые словари из артефактов. Раньше на каждое сообщение заново делались merge с train данными и обсчёт имьютера.
3. Kafka теперь умеет читать пачками (до 100 сообщений), скоринг и flush делаются один раз на пачку, а не на каждое сообщение. Если пачка падает, её обрабатываем по одной строке, чтобы одна плохая запись не ломала остальные; невалидный JSON просто пропускается с записью в лог.
4. Выходное сообщение теперь один JSON-объект, а не массив из одного объекта, как было из-за to_json(orient='records'). Так сообщение соответствует формату из задания (три поля) и любой потребитель топика может читать его напрямую, без распаковки списка. Топик называется scores, как в задании, чтобы название не расходилось с требованиями. На вход, кроме формата {"transaction_id": ..., "data": {...}} от интерфейса, принимается и просто строка test.csv, тогда id генерируется. Это нужно, чтобы сервис можно было проверить, отправив в топик строку из test.csv любым способом, не только через наш интерфейс.
5. Порог фрода вынесен в переменную окружения FRAUD_THRESHOLD в docker-compose.yaml. По умолчанию 0.05, это средний скор на test.csv, при нём около 18% транзакций получают fraud_flag = 1, и результат не выглядит пустым. Порог из соревнования был 0.98, при нём помечается около 0.4%. Чтобы поменять, достаточно исправить значение и выполнить docker compose up -d fraud_detector, пересборка не нужна.
6. Код скоринга модифицирован, что predict_proba вызывается один раз вместо двух, и убран print на каждое сообщение.
7. В docker-compose сервисы теперь стартуют после того, как Kafka реально готова (healthcheck), а не просто после запуска контейнера, а образ kafka-ui закреплён на версии вместо latest.

# Postgres, score_writer и раздел результатов в интерфейсе

Вместе с остальными контейнерами поднимается база Postgres, в которой автоматически создаётся таблица для хранения результатов: идентификатор транзакции, скор, флаг фрода и время записи. Отдельный сервис score_writer читает топик scores и складывает каждый результат в эту таблицу, так что результаты скоринга можно смотреть не только в Kafka, но и в базе. Повторно доставленные сообщения дублей не создают.

Раздел «Результаты скоринга» в интерфейсе берёт данные из этой же базы: по кнопке «Посмотреть результаты» показывает последние фродовые транзакции и гистограмму скоров.
